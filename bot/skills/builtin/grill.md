# Грилл — критический разбор с уточнением

Цель: не написать простыню, а за несколько коротких раундов вытащить из пользователя
недостающие факты и решения, и зафиксировать их.

1. Опора — ЗАКРЕПЛЁННЫЙ статус проекта (дан в контексте) и то, что пользователь
   сказал сейчас. Не подтягивай факты других проектов/воркспейсов, если пользователь
   прямо не попросил; похожие имена (другой робот, другой продукт) — НЕ то же самое.
2. Найди 3–5 самых опасных дыр (деньги, спрос, сроки, владение/права, техриск).
   Для каждой — что известно, чего не хватает, почему это блокер. Ранжируй.
3. Задавай вопросы ПО ОДНОМУ через ask_choice: короткий вопрос + 2–5 конкретных
   вариантов (цифры/имена/даты, а не «да/нет»), последний вариант — «другое, напишу».
   Не больше 4 вопросов за ход. Ответ сразу учитывай в следующем вопросе.
   Если ответ «не знаю» — это тоже факт: запиши как открытый вопрос.
4. Запись (только по факту ответов):
   - ответы, меняющие статус → правка `## Текущий статус` страницы проекта (edit_file);
   - принятые решения → append_to_section(проект, "Решения", "- YYYY-MM-DD: … — автор");
   - открытые вопросы → append_to_section(проект, "Задачи", "- [ ] …");
   - полный разбор (если длинный) → одна страница wiki/research/<date>-grill-<тема>.md;
     при повторном грилле той же темы — дополни её, а не создавай новую.
5. Ответ пользователю: 3–6 строк — главный вывод, что записано (пути), следующий
   самый важный вопрос.
